# Development Workflow

This page covers building, linting, and packaging the composer for development.

## Requirements

The following are expected to be installed:

- Node.js (v24+)
- Podman

## Install and build

```bash
npm ci              # install dependencies
npm run build       # compile src/ → generators/
npm run lint        # lint TypeScript source in src/
```

The `build` script runs `tsc` and then `node scripts/copy-assets.js` to copy
templates and other assets into the compiled `generators/` directory.

## Source layout

| Path | Purpose |
| --- | --- |
| `src/` | TypeScript source for all generators and utilities |
| `src/*/templates/` | EJS/YAML templates (committed, not compiled) |
| `src/util/*-templates/` | Shared templates for helper functions (committed) |
| `generators/**/*.js` | Compiled output — gitignored, regenerated by `npm run build` |

After making changes in `src/`, rerun `npm run build` to recompile before
testing.

## Linking locally

Install the dependencies, compile the TypeScript source, and link it with
`npm link` so Yeoman can find the local installation:

```bash
npm ci
npm run build
npm link
```

You can then run any generator with `npx yo`:

```bash
npx yo nr-repository-composer:gh-maven-build
```

## Building the image

The `Dockerfile` can be built by running `./build.sh`. The local image will be
tagged as `nr-repository-composer`.

## Testing generators locally

Test generators against the `test/` fixtures:

```bash
./nr-repository-composer.sh ./test/mod1 backstage --ask-answered
```

See [Testing](testing.md) for the full testing setup.
